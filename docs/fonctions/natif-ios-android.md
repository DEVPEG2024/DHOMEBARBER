> Période : 5 sept. → 20 oct. 2026. Déplacé tel quel depuis `CLAUDE.md` le 20 oct. 2026 (version du commit 7738a11). Les règles à retenir sont résumées dans `CLAUDE.md` ; ce fichier garde le détail. Quand une session modifie cette fonction, elle met ce document à jour.

### Apps natives (Capacitor)
- Scripts : `npm run cap:sync` (build + sync), `npm run cap:ios`, `npm run cap:android` (build + sync + ouverture Xcode / Android Studio)
- **`npm run android:release`** (ajouté le 5 sept. 2026) : build web → sync Capacitor → incrément de `versionCode` et du dernier segment de `versionName` → bundle signé → téléversement sur la piste **test interne** du Play Console. Options : `--dry-run` (n'écrit rien), `--no-upload` (s'arrête au bundle), `--track=alpha`. Aucune dépendance npm — le JWT du compte de service est signé avec `node:crypto` puis échangé contre un jeton OAuth, comme `lib/nativePush.js`. La signature du `.aab` est vérifiée avant l'envoi. **Identifiants en place depuis le 5 sept. 2026** : compte de service `play-publisher@d-home-barber.iam.gserviceaccount.com` (projet Cloud `d-home-barber`, API *Google Play Android Developer* activée), clé dans `~/.play-console/dhomebarber-play.json` (hors git, chmod 600), invité au Play Console avec : afficher les informations de l'app, afficher la qualité de l'app, « Déployer les applications sur des canaux de test » et, **depuis le 7 oct. 2026** (accordé par l'utilisateur), « Mettre les applications à disposition de tous les utilisateurs… » : il **peut publier en production** (`npm run android:release -- --track=production`, ou promotion d'un versionCode déjà envoyé par l'API `edits` → `tracks/production` → `commit`). Le commit sans modification en attente refuse `changesNotSentForReview` (« Changes are sent for review automatically ») : le script retente sans ce paramètre. Pour refaire l'opération ailleurs : un compte de service Google Play (Google Cloud → activer *Google Play Android Developer API* → IAM → compte de service → clé JSON ; puis Play Console → Utilisateurs et autorisations → inviter cette adresse avec le droit « Gérer les versions »), déposé dans `~/.play-console/dhomebarber-play.json` (ou via `PLAY_SERVICE_ACCOUNT_FILE` / `PLAY_SERVICE_ACCOUNT_JSON`). Sans lui, le bundle est construit et le script explique la marche à suivre
- Le build web (`dist/`) est copié dans les projets natifs par `cap sync` ; les apps chargent le bundle local, pas dhomebarber.fr
- Android : `android/dhomebarber-release.keystore` + `android/keystore.properties` servent à signer les releases Play Store. **Ils ne sont dans aucun git : à sauvegarder ailleurs, sans eux aucune mise à jour Play Store n'est possible.**
- État précédent (10 septembre 2026) : **iOS 1.0 (build 6) soumis à la review Apple le 10 sept. 2026 à 01h38 (Paris)**, reviewSubmission `439a9ec8-d74d-4f23-b1ee-9d9767f6e0df`, `CURRENT_PROJECT_VERSION = 6` dans le pbxproj (prochain envoi = 7), mise en ligne manuelle après approbation. Le build 5 avait été refusé le 9 sept. 2026 (**Guideline 4 – Design**, testé sur iPad Air 11" M3 sous iPadOS 26.6 : le clavier recouvrait les champs de connexion ; l'app est iPhone seulement, elle tourne sur iPad en mode compatibilité et Apple la teste quand même sur iPad). Correctif dans le build 6 (voir « Clavier » ci-dessous), notes de review complétées via l'API (paragraphe « [Build 6 — iPad keyboard fix] » en tête), ancienne soumission 50bedf7e annulée. Recette d'archive / envoi : **avant `xcodebuild archive` : `npm run cap:sync`, puis vérifier que `capacitor-swift-pm` est à la version de `@capacitor/ios` dans `ios/App/CapApp-SPM/Package.swift` et dans `Package.resolved`** (sinon l'app embarque l'ancien Capacitor iOS, 8.2.0 au 18 oct. 2026, vulnérable GHSA 8.0.0 → 8.3.4) ; `security unlock-keychain` sur le trousseau `dhomebarber-build`, `xcodebuild archive` Release avec `OTHER_CODE_SIGN_FLAGS="--keychain …"`, puis `-exportArchive` avec un `exportOptions.plist` (method `app-store-connect`, destination `upload`, signingStyle `manual`, profil « D Home Barber App Store ») et les options `-authenticationKey*` ; traitement VALID en ~3 min ; attacher le build à la version (`PATCH appStoreVersions/{id}/relationships/build`), créer la `reviewSubmission` **après** que l'ancienne soit passée de CANCELING à COMPLETE (sinon « Item is already present »), ajouter l'item version, `PATCH submitted=true`.
- **Clavier sur iOS (règle, 10 sept. 2026)** : `Keyboard.resize = 'native'` dans `capacitor.config.ts` (jamais `body` : sur iPad en mode compatibilité la fenêtre n'est pas réduite et le clavier recouvre les champs) + `initKeyboardHandling()` dans `src/lib/capacitor.js` (si `innerHeight` n'a pas rétréci entre `keyboardWillShow` et `keyboardDidShow`, la hauteur du clavier devient `--keyboard-overlap`, posée en `padding-bottom` par `body.keyboard-open` ; repli `visualViewport` qui ne fait que compléter ; champ actif ramené au centre de la zone visible). **Jamais la hauteur du clavier en plus d'une fenêtre déjà réduite (20 oct. 2026)** : sur le simulateur iPad (iPadOS 26.3) la WebView est réduite APRÈS `keyboardDidShow`, et sur Android le module clavier (`resizeOnFullScreen`) la réduit AVANT `keyboardWillShow` ; le recouvrement était alors compté deux fois et la demande de privatisation plein écran (`bottom: var(--keyboard-overlap)`) s'écrasait en une bande de 200 px. Correctif : écouteur `resize` qui ramène le recouvrement au réel quand la fenêtre rétrécit clavier ouvert, et sur Android seulement, fenêtre plus courte que l'écran d'au moins le clavier = déjà réduite (pas sur iOS : en mode compatibilité iPhone la taille d'écran déclarée n'est pas sûre, et le cas « jamais réduite » doit garder la hauteur du clavier). Le module Android transmet la hauteur en pixels de page (divisée par la densité). Vérification attendue avant tout envoi : simulateur **iPad Air 11-inch (M3)**, tap sur Email / Mot de passe / dernier champ de l'inscription **et le message de la demande de privatisation**, capture avec clavier ouvert (`xcrun simctl io <udid> screenshot`, tap via `osascript` → `System Events` → `tell process "Simulator"` → `click at {x, y}` ; le premier clic ne fait qu'activer la fenêtre). Pièges du simulateur : après un raccourci (Cmd+Maj+K, Cmd+V) la touche Commande peut rester « enfoncée » côté iOS (touchers ignorés, Tab = sélecteur d'apps) : envoyer `key down` / `key up` de chaque modificateur ; pour atteindre un écran profond sans défilement, modifier seulement la copie installée (`xcrun simctl get_app_container <udid> fr.dhomebarber.app app` → `public/index.html`, script `history.replaceState` vers `/events?demande=anniversaire`), jamais le projet ; les événements souris de `swift`/CGEvent ne passent pas (autorisation macOS) ; l'émulateur Android (image Google Play) exige l'autorisation de débogage à l'écran et sa console (`nc localhost 5554`, jeton `~/.emulator_console_auth_token`) sait faire `screenrecord screenshot <dossier>`. `.login-logo` se replie quand le clavier est ouvert. Incrémenter `versionCode` / `CURRENT_PROJECT_VERSION` avant chaque envoi aux stores. Les builds natifs embarquent le bundle web : après une modification frontend, refaire `npm run cap:sync` puis un nouveau build store pour que les apps l'aient (le web dhomebarber.fr, lui, est à jour dès le push).
- **Contrôle clavier du 21 oct. 2026 (build 16), pièges en plus** :
  - **Clavier logiciel absent** : I/O → Keyboard → « Connect Hardware Keyboard » coché. Le décocher dans le menu (`click menu item … of menu bar item "I/O"` par `osascript`) ou, plus sûr, quitter Simulator, `defaults write com.apple.iphonesimulator ConnectHardwareKeyboard -bool false`, relancer l'iPad (remettre `true` après). Pour taper un texte (`keystroke`), il faut au contraire le clavier matériel branché : basculer le temps de la saisie.
  - **Touchers ignorés** après une navigation au clavier (Tab) ou un raccourci : relancer l'app (`simctl terminate` puis `launch`) plutôt que de s'acharner ; Tab peut poser le focus sur « Envoyer ma demande », ne plus appuyer sur aucune touche ensuite.
  - **Fenêtre** : `set position of window 1 to {100, 40}` → fenêtre 686 × 995, échelle 0,8366 et barre de 7,8 px pour passer des pixels de la capture (1640 × 2360) aux clics : `x = 100 + px/2 × 0,8366`, `y = 47,8 + py/2 × 0,8366`.
  - **Demande de privatisation** : `/events` exige une session ; se connecter avec le compte de démonstration `reviewer@dhomebarber.fr` (mot de passe dans `~/.appstoreconnect/dist/review-account.txt`). Pour atteindre le message sans glisser, ajouter à la copie installée un script qui fait `scrollIntoView` sur le premier `textarea`. Désinstaller la copie ensuite (efface la session). Vérifier en base qu'aucune demande n'est partie.
  - **Écran blanc ~30 s au tout premier lancement** après le démarrage du simulateur sur un Mac chargé : normal, une réinstallation affiche la connexion en moins de 10 s (vérifié). En Debug, la console JS s'obtient par `xcrun simctl launch --console-pty`.
- **Langue et sauvegarde des projets natifs (règle, tour 8 du 18 oct. 2026, dossiers hors git)** : iOS choisit la langue des composants système (sélecteurs de date et d'heure, Copier / Coller, sélecteur de photos) parmi les localisations du bundle. Tout projet `ios/` doit déclarer `fr` **avant le premier archivage** : `Info.plist` avec `CFBundleDevelopmentRegion = fr` et `CFBundleLocalizations = (fr, en)`, `project.pbxproj` avec `knownRegions = (en, fr, Base)` et `developmentRegion = fr` (fait le 18 oct., à livrer avec iOS build 12 ; vérifier sur un simulateur iPhone en français). Android : `android:allowBackup="false"` dans `AndroidManifest.xml` (fait le 18 oct., à livrer avec versionCode 12) : sinon le jeton de session du `localStorage` de la WebView part dans la sauvegarde Google et se restaure sur un autre téléphone. À refaire dans tout nouveau projet `android/`.
